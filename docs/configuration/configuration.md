# Configuration

[← Docs index](../README.md)

After `init`, configuration lives as several YAML files under `env/<name>/` (the default name is `local`). You edit those files, then run `install`. There is no single INI file. Secrets (Redis password, gateway keys, and so on) are generated by the installer; do not put them in git.

```bash
./toolkit_manager.sh init agent-toolkit --env <env>
```

Omit `--env` to use `local`.

> Older docs and the standalone monolith used `core/inventory/agentic-config.cfg` and `vault.yml`. Those files are gone. The mapping at the bottom of this page is only for people migrating from that layout.

## The files

These are the files `init` writes under `env/local/`. Change the copies here; they are what `install` reads.

| File | What it is for |
|---|---|
| `global_config.yaml` | Cluster-wide: domain, TLS, storage, proxy, bring-your-own kubeconfig |
| `config.inference.yaml` | Inference layer: which routers to install, and guardrail flags |
| `models.yaml` | Catalog of model names, Hugging Face ids, CPU, and memory. Deploy with `llm_services_autodeploy_models` or `./model-manager deploy <name>` |
| `config.agent-toolkit.yaml` | Toolkit knobs: auth, models, namespaces, Redis, pgvector, sandbox, KubeRay |
| `nodes.yaml` | Which nodes are in the cluster (`nodes_control_plane`, `nodes_workers`). Install regenerates `inventory/hosts.yaml` from it |

### `global_config.yaml`

```yaml
base_domain_name: inteltoolkits.ai
gateway_tls_mode: selfsigned     # selfsigned | custom
# gateway_tls_mode: custom
# gateway_tls_cert_file: /path/to/cert.pem
# gateway_tls_key_file: /path/to/key.pem
# existing_kubernetes: /path/to/kubeconfig   # omit to let the installer create Kubernetes
storage_backend: local-path      # local-path | nfs | ceph | netapp-trident | custom
# object_store_backend: seaweedfs # S3 store for Loki, Tempo, and Langfuse: seaweedfs | external
# http_proxy: http://proxy.corporate.com:8080
# https_proxy: http://proxy.corporate.com:8080
# no_proxy: localhost,127.0.0.1,.svc,.cluster.local
```

| Setting | Effect |
|---|---|
| `base_domain_name` | Public hostname of the API. Must match DNS/`/etc/hosts` and the certificate. |
| `gateway_tls_mode` | `selfsigned` for a lab. `custom` plus cert/key paths for the cert from [Prerequisites](../getting-started/prerequisites.md). |
| `existing_kubernetes` | Path to a kubeconfig if the cluster already exists. Omit to provision Kubernetes. |
| `storage_backend` | Where PVCs go. `local-path` on one node; `nfs`, `ceph`, `netapp-trident`, or `custom` on several. NetApp: [NetApp ONTAP](https://github.com/intel/toolkit-manager/blob/main/docs/deployment/netapp-ontap.md) in Toolkit Manager |
| `object_store_backend` | S3 store for Loki, Tempo, and Langfuse. Default `seaweedfs`; use `external` for your own S3 endpoint |
| `http_proxy` / `https_proxy` / `no_proxy` | [Corporate proxy](../deployment/proxy.md). `no_proxy` must include `.svc` and `.cluster.local`. |
| `kubernetes_cluster_cidr` | Pod CIDR of a bring-your-own cluster. Set this when OpenShell is on so LiteLLM can admit sandbox traffic from that range. |

#### API sign-in (`auth_type`)

Set `auth_type` in `config.agent-toolkit.yaml` (or `config.inference.yaml`). `init agent-toolkit` seeds `auth_type: litellm_vkey`. Leave that default for the LiteLLM gateway, Langfuse traces, and the content-safety guardrail. Set `auth_type: jwt` for Keycloak JWT on the Envoy AI gateway instead.

| You want | Set |
|---|---|
| LiteLLM virtual keys (default) | `auth_type: litellm_vkey` |
| Keycloak JWT on the AI gateway | `auth_type: jwt` |

`config.agent-toolkit.yaml` loads **after** `config.inference.yaml`, so `auth_type`, `guardrails_enabled`, `hybrid_router_enabled`, and the `litellm_*` keys here override the inference layer.

Legacy: `auth_provider` in `global_config.yaml` (`litellm` / `keycloak`) is deprecated and mapped to `auth_type`. Prefer `auth_type` only; if both are set they must agree or preflight fails.

### `config.inference.yaml`

This file turns inference routers (and related guardrail flags) on or off. **Which chat models deploy is not here.** Put those names in `llm_services_autodeploy_models` in `config.agent-toolkit.yaml`.

**What routing is.** By default, an application names one deployed model (for example `qwen2-5-coder-14b`) on every `/v1/chat/completions` call. Routing replaces that with a virtual model name. The stack looks at the prompt, picks which real model should answer, and returns the completion. The client still calls the same gateway URL; only the `"model"` value changes.

**Why it matters.** You often run several models at once: a small fast one for simple questions, a larger one for hard code or reasoning, and maybe a specialist for a category such as coding. Without routing, every client has to know which model to call. With routing, clients keep one name, and the stack sends easy prompts to the cheap model and hard prompts to the capable one. That cuts cost and latency without changing the application.

Routing is optional. A request that names a real model goes straight to that model. A virtual model name picks a router instead. There are two kinds of routing to choose from.

#### LiteLLM-based routing

Complexity, hybrid, and semantic routers run through the LiteLLM gateway. The flag in this file is for the toolkit **hybrid router**: `hybrid_router_enabled` defaults to `true`, and install creates the virtual model `hybrid-router`. That router classifies how complex the prompt is, then selects a deployed model. Details: [Routing](routing.md) and [Hybrid router](hybrid-router.md).

#### vLLM-SR

vLLM Semantic Router is separate from the LiteLLM options above. Set `vllm_sr_enabled: true` to install it. Clients call the virtual model `vllm-sr/auto`; the router classifies by intent or category and selects a deployed model. Details: [Routing](routing.md) and [vLLM semantic router](semantic-router.md).

```yaml
hybrid_router_enabled: true
# vllm_sr_enabled: false
```

### `models.yaml`

This file is the catalog. A name in `llm_services_autodeploy_models` must match a `name` here. Per-model CPU and memory are set on the same entry. There is no `autodeploy` flag.

### `config.agent-toolkit.yaml`

```yaml
auth_type: litellm_vkey          # litellm_vkey | jwt
llm_services_autodeploy_models: ["qwen2-5-coder-14b"]
redis_stack_enabled: true
pgvector_enabled: true
agent_sandbox_enabled: true
kuberay_enabled: false
openshell_enabled: false
```

| Setting | Default | Meaning |
|---|---|---|
| `auth_type` | `litellm_vkey` | API sign-in. Leave the default for LiteLLM; set `jwt` for Keycloak on the AI gateway |
| `llm_services_autodeploy_models` | `["qwen2-5-coder-14b"]` | Models deployed during `install`. `[]` installs with no chat model. Deploy others later with `./model-manager deploy <name>` |
| `guardrails_enabled` | on when `auth_type` is `litellm_vkey` | Set `false` to keep LiteLLM but turn off content-safety screening. [Guardrails](guardrails.md) |
| `hybrid_router_enabled` | `true` | Creates the `hybrid-router` virtual model. Overrides the same key in `config.inference.yaml`. [Hybrid router](hybrid-router.md) |
| `litellm_public_paths` | `[]` | Paths published on LiteLLM’s route. Empty means all paths (admin UI and key API stay LiteLLM-authenticated) |
| `litellm_allow_pod_network` | follows `openshell_enabled` | When OpenShell is on, LiteLLM admits API calls from the pod network. [OpenShell](../reference/openshell.md) |
| `litellm_allowed_namespaces` | gateway, litellm, sandbox, kuberay | Namespaces LiteLLM admits on the mesh. Add your own ambient-labelled agent namespace here |
| `node_preflight_enabled` | `true` | Runs `playbooks/preflight-check.yml` at the start of install (report only). [Validate](../faq-and-troubleshooting/validate.md) |
| `redis_stack_namespace` | `redis` | Namespace for Redis Stack |
| `redis_stack_storage_class` | `""` | PVC StorageClass. Empty uses the cluster default |
| `redis_stack_persistence_size` | `10Gi` | Redis PVC size |
| `pgvector_namespace` | `pgvector` | Namespace for PostgreSQL + pgvector |
| `pgvector_database` / `pgvector_username` | `agentdb` / `agentuser` | Database and role |
| `pgvector_storage_size` | `20Gi` | pgvector PVC size |
| `pgvector_storage_class` | `""` | PVC StorageClass. Empty uses the cluster default |
| `agent_sandbox_namespace` | `agent-sandbox-system` | Sandbox operator and pods |
| `agent_sandbox_python_warm_pool_size` | `5` | Pre-warmed sandbox pods. Costs CPU/RAM on install; `0` disables. [Agent sandbox](../reference/agent-sandbox.md) |
| `kuberay_enabled` | `false` | Set `true` to install Ray. [KubeRay](../reference/kuberay.md) |
| `redis_stack_enabled` / `pgvector_enabled` / `agent_sandbox_enabled` | `true` | Set `false` to skip that component |
| `openshell_enabled` | `false` | Policy layer on the agent sandbox. [OpenShell](../reference/openshell.md) |
| `keycloak_agent_config_enabled` | on by default | Creates the `agent-toolkit` realm on the platform Keycloak. The enable condition still keys off legacy `auth_provider` (unset counts as Keycloak), so the realm installs even when `auth_type` is `litellm_vkey`. Set `false` to skip it |
| `keycloak_agent_realm` | `agent-toolkit` | Realm name |

Source defaults (copied at `init`): `config.yaml` at the root of this repo.

## Hugging Face token

The Hugging Face token is not stored in YAML. Export it in the same shell that runs `install`:

```bash
export HF_TOKEN=hf_...
```

Skip this if every model in `llm_services_autodeploy_models` is ungated, or if that list is `[]`. The default `qwen2-5-coder-14b` is ungated.

## If you used the old INI file

The standalone stack stored flags in `agentic-config.cfg`. Toolkit Manager maps those flags to the YAML files above. Use this table only if you are migrating; new installs should ignore the left column.

| Old `agentic-config.cfg` | Now |
|---|---|
| `deploy_redis` / `deploy_pgvector` / `deploy_agent_sandbox` | `redis_stack_enabled` / `pgvector_enabled` / `agent_sandbox_enabled` |
| `deploy_kuberay=on` | `kuberay_enabled: true` |
| `deploy_llm_models`, `models=` | `llm_services_autodeploy_models`; `./model-manager deploy <name>` |
| `deploy_guardrails=on` | `guardrails_enabled` (on when `auth_type` is `litellm_vkey`) |
| `deploy_observability=on` | `observability_enabled` in `global_config.yaml` |
| `deploy_vllm_sr` | `vllm_sr_enabled` in `config.inference.yaml` |
| `cert_file` / `key_file` | `gateway_tls_mode: custom` + cert/key paths |
| `cluster_url` | `base_domain_name` |
| `hugging_face_token` | `export HF_TOKEN=...` |
| `http_proxy` / `https_proxy` / `no_proxy` | Same keys in `global_config.yaml` |
| `deploy_kubernetes_fresh` | Omit `existing_kubernetes` and the installer creates the cluster |
| `vault.yml` | Removed: installer generates secrets |

In this release through Toolkit Manager: rack-scale fabric (`rack_scale_enabled`) and Intel® Arc™ GPUs (`./model-manager deploy … --server vllm-xpu`). See [Rack-scale](../deployment/rack-scale.md) and [Intel® Arc™ GPU](../deployment/intel-arc.md). Not in this release: the Flowise plugin (`deploy_agenticai_plugin`) and `air_gapped`. Kata Containers (`kata_containers_enabled`, `kata-fc` / `kata-qemu`) is a sandbox option and needs `agent_sandbox_enabled: true`. The steps are in [Agent sandbox](../reference/agent-sandbox.md#kata-containers). Docker Compose is a separate path: [Docker](../deployment/docker.md) uses `docker/deploy.sh`, not `./toolkit_manager.sh install`.

## Next steps

After you change YAML, re-run `./toolkit_manager.sh install agent-toolkit`. The toolkit roles (Redis, pgvector, sandbox, KubeRay, OpenShell) upgrade on every run, so their settings take effect without a teardown. The [single-node quickstart](../getting-started/quickstart.md) shows a first working set of values. In-cluster URLs for Redis, pgvector, and the sandbox are in the [backend connection reference](../reference/backend-connections.md). Content-safety screening is covered in [Guardrails](guardrails.md). Virtual model names are covered in [Routing](routing.md). To remove the agent layer and install again, see [Decommission and redeploy](../deployment/decommission.md). If install fails, see [Troubleshooting](../faq-and-troubleshooting/troubleshooting.md).
